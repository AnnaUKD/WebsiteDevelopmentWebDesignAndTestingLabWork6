# Практична робота №6 — Screen States та дизайн-токени

Каталог курсів на чистому HTML/CSS/JS (без бібліотек і фреймворків).

## Що реалізовано
- Чотири взаємовиключні стани екрана: `loading` (skeleton з `@keyframes`), `content`, `empty` (SVG-іконка + кнопка), `error` (код помилки + «Повторити спробу»).
- `renderState(stateName)` ховає неактивні блоки класом `.is-hidden`; `element.style` не використовується.
- Панель перемикання станів, кнопка «Оновити» (loading 1,8 с → content через `setTimeout`).
- Перехід в `empty` при видаленні всіх карток або фільтрі без збігів; кнопка в empty повертає список.
- Трирівневі токени в `css/tokens.css` (Primitive → Semantic → Component); у `styles.css` немає HEX/RGB і «сирих» px.
- Сторінка `ui-kit.html`: кнопки (Primary/Secondary/Danger), поля з `<label>` і помилкою валідації, картки; стани Default/Hover/Focus/Disabled/Error.
- Перемикач світлої/темної теми (спільний `js/theme.js`, вибір зберігається в localStorage): перевизначаються лише семантичні токени в `[data-theme="dark"]`.

## Структура
```
index.html
ui-kit.html
tokens.css   # токени
styles.css   # стилі компонентів
app.js        # стани та логіка
theme.js      # перемикач теми
```

## Запуск
Відкрити `index.html` у браузері. Для публікації: GitHub → Settings → Pages → Branch `main` / root.

## Відповіді на контрольні запитання

**1. Різниця між веб-сайтом і веб-додатком.**
Інформаційний сайт здебільшого показує статичний контент, який читають зверху вниз, тому стан у нього, по суті, один. Веб-додаток має багато даних на екрані (таблиці, списки, фільтри) і постійно змінюється від дій користувача та відповідей сервера. Тому для кожного екрана доводиться окремо проєктувати завантаження, дані, порожній результат і помилку.

**2. Призначення Empty State та Loading/Skeleton (UX).**
Skeleton показує, що додаток працює, і повторює майбутню структуру сторінки: інтерфейс не «стрибає» і не здається завислим. Empty State пояснює, чому екрана немає даних (перший запуск чи фільтр без результатів) і дає наступну дію (CTA), щоб користувач не опинився перед порожнім місцем.

**3. Wireframe, Mockup, Prototype.**
Wireframe — чорно-білий каркас: розташування блоків і структура, без кольорів і шрифтів. Mockup — статичний макет із фінальним візуальним стилем (кольори, типографіка, зображення). Prototype — інтерактивна модель, у якій можна клікати та проходити сценарії, щоб перевірити логіку до розробки.

**4. Ієрархія токенів і чому тема змінюється на семантичному рівні.**
Primitive — сирі значення (`--blue-600: #2563eb`). Semantic — ролі, що посилаються на примітиви (`--color-primary`, `--color-bg`). Component — токени конкретних елементів (`--btn-primary-bg`). Компоненти посилаються на семантику, а не на кольори, тому для темної теми достатньо перевизначити семантичні токени — всі компоненти оновляться самі, без змін у класах. Примітиви змінювати не потрібно, а на рівні компонентів довелося б переписувати кожен елемент.

**5. Дизайн-система й узгодженість макета та коду.**
Токени — спільна мова: ті самі назви й значення є і в макеті (Figma variables), і в коді (CSS Custom Properties). Дизайнер змінює значення в одному місці, розробник — так само, тож відступи, кольори й компоненти не розходяться, а нові екрани збираються з готових стандартизованих частин.
